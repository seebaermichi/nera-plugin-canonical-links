## [2.2.1] - 2026-07-22

### Fixed

-   pages that do not set the `page_identifier` (`slug` by default) are no
    longer cross-linked to each other as translations. The lookup compared the
    raw values, so `undefined === undefined` matched and every page missing the
    key was declared a language variant of the first other-language page that
    was also missing it. The visible symptom was on pages **generated** by
    another plugin, which never carry frontmatter: on a trilingual site every
    `plugin-tags` overview page pointed at the same unrelated tag page in each
    other language. Such pages now get a canonical link and no alternates
-   a trailing slash on the origin no longer produces a doubled slash.
    `https://example.com/` yielded `https://example.com//page.html` — a
    duplicate URL handed to search engines as the authoritative one
-   README: the Usage snippet used `include vendor/plugin-canonical-links/index`
    with no leading slash. That is relative to the *including file*, so from a
    layout in `views/layouts/` — where Nera layouts live — it resolved to
    `views/layouts/vendor/…` and failed the build with `ENOENT`. Now documents
    the root-absolute `include /vendor/…` form, with the relative form given as
    the fallback for Nera v4.1.x–v4.2.x
-   README: two headings carried corrupted bytes (`U+FFFD`) instead of their
    emoji
-   README: stated Node.js >= 18; the package has required >= 20.0.0 since 2.2.0

### Added

-   README: a `## 📊 Generated Output` section documenting `meta.canonicalLink`
    and `meta.alternateLinks` — their shapes, and the two cases a hand-written
    template must guard for (`alternateLinks` is an empty array when no
    languages are configured; both keys are absent when no origin resolves)
-   README: frontmatter requirements stated as rules — a page without `lang`
    silently gets no alternate links, and translations must share an identical
    identifier value
-   README: a section on **pages generated by other plugins**. Plugin order is
    `start:` → alphabetical → `end:`, so this plugin runs before `plugin-tags`
    and never sees the pages it generates. Documents listing
    `plugin-canonical-links` under `end:` in `config/plugin-order.yaml`
    (Nera v4.2.0+), verified against a real trilingual build
-   README: a `## 🤝 Contributing` section linking to the Nera contributing guide
-   README: the Compatibility block now states the `@nera-static/plugin-utils`
    range and justifies the Nera floor by naming the feature each version adds

### Changed

-   README: notes that the config file is optional when `origin` is set in
    `config/app.yaml`, and that the packaged config is documentation only
-   README: Development shows `npx vitest run`; `npm test` is watch mode

## [2.1.0] - 2026-07-19

### Fixed

-   no longer emits `<link rel="canonical" href="undefined/...">` on every page
    when no origin is configured. That markup was worse than none — it told
    search engines the authoritative URL was a broken string, and nothing was
    printed to warn about it. The plugin now warns once and leaves pages
    untouched

### Added

-   `publish-template` command (`npx nera-canonical-links`), so the shipped
    templates can be copied into `views/vendor/` like every other plugin.
    Previously there was no publish path at all and the README worked around it
    by including straight out of `node_modules/`
-   `--force` to re-publish over existing templates, discarding local edits

### Changed

-   `@nera-static/plugin-utils` range widened to `^1.2.0`, which is what makes
    `partials/` publish alongside `index.pug`
-   config is resolved per call rather than at module load
-   README: `app_origin` was documented as overriding `app.origin`. It is the
    other way round — `app.origin` wins. The docs now match the code
-   README: documents that omitting `available_languages` silently disables
    alternate links

### Removed

-   dead `if (!config)` guard — `getConfig` returns `{}`, so it never fired
